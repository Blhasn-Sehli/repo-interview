Can you explain your AI's own code?

repo-interview reads your repository or pull request and asks what an interviewer or reviewer would. Every question cites real code, and a verifier throws out any question about code that doesn't exist.

The verifier

Questions about code that exists. Only.

Can you explain the main components of the Express.js application and how they interact?
keptlib/application.js › init
How does Express.js handle errors, and what is the role of middleware in this process?
keptlib/application.js › error
What is the purpose of the Router class in Express, and how can it be used to handle different routes?
droppedlib/router.js › handler
file not found: lib/router.js

These three came from one real run on express. The third sounds right: older Express had a lib/router folder. Today's Express moved its router into a separate package, so the file the model cited doesn't exist.

A model that invents a citation would quiz you on code you don't have. repo-interview checks every cited file and symbol against the repository and drops the question before you see it. For pull requests, the cited file must also be one the PR changed.

Two checks, both reported: strict (exactly as written) and fair (also accepts a path without its folders when only one file matches, and Class::method).

How often questions cite real code

10 public repositories in 10 languages, 8 questions each, the small local model qwen2.5-coder:3b, averaged over 3 runs. The verifier drops the rest before you see them.

Every model reply is recorded, so anyone can recheck these numbers offline. Not measured yet: how well grading agrees with a human, and how useful testers find the questions. Method and per-repo results.

Strict check (exact path and symbol)90.7%
Fair check (folder-less paths, Class::method)92.8%
Invented citations shown to you0

Single runs ranged 86.3–95.8% strict and 90.0–95.8% fair.

Untrusted code, handled as data

Built for code you didn't write

Never runs repo code

Files and diffs are read as text. The prompts tell the model they are data, not instructions.

Stays inside the project

The MCP tools refuse absolute paths and anything outside the project folder, symlinks included.

Safe PR comments

HTML is escaped and @mentions broken, so a hostile diff can't make the bot ping or inject anything.

Never blocks a merge

Failures become warnings. Scoring reads the PR's code in a separate folder and never executes it.
